# Editing and revision

## Match the authorized depth

Read the passage before deciding that it needs a rewrite. For a file edit, identify
the actual file and requested span; do not infer a filename from the first word of
the user's request. Read enough surrounding context to resolve references and
scientific scope. If several files are plausible, resolve the ambiguity before
editing. A user's selection is the edit boundary, not the read boundary.

Copyediting corrects mechanics and unambiguous local problems. Line editing can
recast sentences and improve paragraph continuity. Structural revision can move
and reshape the requested argument. Drafting supplies new prose from evidence.
An unspecified “polish” authorizes restrained editing, not structural revision.

Keep untouched portions byte-identical for a surgical file edit. Do not normalize
unrelated whitespace, citation commands, notation, or line endings. Preserve the
author's effective sentences. If a larger problem falls outside the requested
scope, identify it briefly without performing the larger revision.

## Diagnose before polishing

For a substantial revision, ask:

1. What is the actual claim, and what supports it?
2. Does each next step have the context the reader needs?
3. Can the same reasoning be expressed more directly?
4. Did the revision lose a condition, change a comparison, or imply more certainty?

These are priorities, not four mandatory passes. Return to the argument if sentence
editing exposes a missing premise. Supply a connection only when the sources
support it; otherwise flag the gap. Distinguish an exposition problem from an
unresolved scientific question.

## Reviewer feedback

Map the supplied comments to passages and requested actions. For a large revision,
keep a compact working map of addressed, unresolved, and unsupported requests.
Use it to complete the authorized work; do not require a separate approval of the
map when the user has already authorized those changes.

Do not treat a reviewer's assertion as established evidence. If a requested change
requires new analysis, identify that requirement and revise only what the existing
evidence supports. Keep rebuttal prose separate from manuscript prose. Describe
completed changes accurately, with locations when available; never claim an
experiment or revision was performed when it was only proposed.

## Delivery

For review-only requests, provide actionable observations and short examples
without changing source files. For edits, deliver the revised prose or files and
only the notes needed to explain consequential changes or unresolved problems.
Do not append generic praise, a repeated summary, or `% REVISED`/`% POLISHED`
comments unless requested.
